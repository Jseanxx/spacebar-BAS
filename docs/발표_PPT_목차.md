## 2. 프로젝트 목표 및 소개 페이지

문제 정의와 프로젝트 목표는 한 페이지에서 함께 설명한다.

한 페이지에서 모든 구현 내용을 자세히 말하려고 하면 산만해진다. 따라서 “우리가 무엇을 만들었는지”를 아래 5단계 흐름으로 압축한다.

```text
기업형 피해 환경 구축
-> MITRE ATT&CK 캠페인 설계
-> ELK/SIEM 탐지 체계 구축
-> BAS 검증 도구로 탐지 점검
-> DF/IR 보고서와 블루팀 플레이북 작성
```

추천 소개 문장:

> SpaceBar는 실제 기업 환경에 가까운 피해 환경을 직접 구축하고, MITRE ATT&CK 기반으로 공격 시나리오를 캠페인 형태로 설계한 뒤, ELK 기반 SIEM에서 로그 수집과 탐지 룰을 구성하는 프로젝트입니다. 여기서 끝내지 않고 BAS 형태의 점검 도구로 탐지 룰이 실제로 동작하는지 확인하고, 부족한 탐지 포인트를 보완하며, DF/IR 분석 보고서와 블루팀 대응 플레이북까지 연결하는 것을 목표로 했습니다.

핵심 메시지:

- 단순 공격 재현 프로젝트가 아니다.
- 기업형 환경, 공격 캠페인, SIEM 탐지, BAS 점검, 대응 산출물을 하나의 흐름으로 연결한 프로젝트다.
- 최종 목표는 “공격을 했다”가 아니라 “공격이 어떤 로그를 남기고, 그것을 어떻게 탐지하고 대응할 수 있는지 확인했다”이다.

## 3. 페이지별 설명

### 전체 아키텍처

CI/CD 서버, 애플리케이션 서버, DB 서버, 로그 분석 서버 등 전체 환경 구성을 보여준다.

핵심 메시지:
실제 기업 환경처럼 역할을 분리하고, 공격 흐름과 로그 수집 흐름을 함께 볼 수 있도록 설계했다.

### 팀 역할 분담

각 팀원이 어떤 환경, 공격 캠페인, 탐지/대응 산출물을 맡았는지 보여준다.

핵심 메시지:
역할이 흩어진 것이 아니라, 공통 산출물 형식과 전체 목표 안에서 각자 역할을 나누어 수행했다.

### 프로젝트 진행 로드맵

주차별로 환경 구축, 캠페인 작성, 로그 수집, 탐지 룰 작성, BAS 검증, 보고서/플레이북 작성이 어떻게 진행됐는지 보여준다.

핵심 메시지:
최종 발표 직전에 급하게 만든 것이 아니라, 계획에 따라 환경 구축부터 검증과 산출물 정리까지 단계적으로 진행했다.

### MITRE ATT&CK 캠페인 설계

공격 흐름을 MITRE ATT&CK Technique 단위로 매핑한 과정을 설명한다.

핵심 메시지:
ATT&CK을 단순한 공격 기법 분류표가 아니라, 어떤 공격 단계가 탐지 가능한지 확인하는 커버리지 기준으로 활용했다.

### ELK/SIEM 탐지 체계 구축

로그 수집과 분석 환경을 어떻게 구성했는지 설명한다.

핵심 메시지:
각 서버에서 발생하는 로그를 ELK로 수집하고, Kibana에서 탐지 근거를 확인할 수 있도록 SIEM 형태의 분석 환경을 구성했다.

### BAS 검증 도구 구현

Mini BAS 형태로 Technique별 행위를 실행하고 탐지 룰이 실제로 동작하는지 점검한 부분을 설명한다.

핵심 메시지:
상용 BAS를 완성한 것이 아니라, MITRE ATT&CK 캠페인에 매핑된 Technique을 안전한 BAS 모듈로 실행하고 ELK/Wazuh 로그와 비교해 탐지 가능 여부를 확인하는 구조를 만들었다.

### DF/IR 분석 보고서 작성 프로세스

DF팀의 로그 무결성 확보와 분석 보고서 작성 흐름을 설명한다.

핵심 메시지:
원본 로그를 바로 건드리지 않고 Elasticsearch alerts 인덱스 스냅샷과 해시값을 확보한 뒤, 별도 분석용 ELK 환경에 복원해 Timesketch 기반 분석과 태깅을 진행했다. 이를 바탕으로 DF/IR 보고서 작성까지 연결했다.

추천 흐름:

```text
공격 수행
-> ELK alerts 로그 생성
-> 스냅샷 생성
-> 원본 파일 압축 및 해시값 확보
-> 분석용 ELK에 복원
-> Timesketch 분석/태깅
-> DF/IR 보고서 작성
```

### 블루팀 대응 플레이북

탐지 이후 운영자가 어떤 순서로 확인해야 하는지 정리한 부분을 설명한다.

핵심 메시지:
공격 단계별 탐지 근거, 후속 조사 방향, 대응 흐름을 정리해 단순 탐지 룰 작성에서 끝나지 않고 실제 대응 절차로 연결하려 했다.

### 프로젝트 시연

전체 기능을 길게 보여주기보다 핵심 흐름만 짧게 보여준다.

핵심 메시지:
캠페인 선택, BAS 실행, ELK 탐지 확인, 결과 확인의 흐름이 실제로 연결되어 있음을 보여준다.

### 최종 결과 요약

최종 산출물을 한 장에 모아 보여준다.

핵심 메시지:
기업형 피해 환경, ATT&CK Campaign, ELK/SIEM, 탐지 룰, BAS 검증 도구, DF/IR 보고서, 블루팀 플레이북까지 결과물이 목표와 연결되어 있음을 보여준다.

### 한계 및 개선 방향

프로젝트의 부족한 점을 숨기지 않고, 다음 단계 고도화 방향을 제시한다.

핵심 메시지:
현재는 Mini BAS MVP에 가깝고, 향후에는 run_id marker 기반 검증, Atomic/Chain/Full Campaign 실행 모드 분리, Detection Gap 분석, 보고서 자동화, Agent 운영 체계 강화가 필요하다.

### 배운 점

기술 나열보다 프로젝트를 통해 얻은 관점을 정리한다.

핵심 메시지:
침해사고 대응은 공격을 재현하는 것만으로 끝나지 않는다. 어떤 로그가 남고, 어떤 근거로 탐지할 수 있으며, 그 결과를 어떻게 대응 절차와 보고서로 연결할지까지 보는 과정이라는 점을 배웠다.
